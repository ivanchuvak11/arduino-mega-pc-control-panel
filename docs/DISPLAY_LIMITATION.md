# Обмеження симуляції дисплея

## Обраний дисплей

Для фізичного прототипу обрано монохромний OLED **SSD1309 2,42″** з
роздільною здатністю 128×64 та інтерфейсом I2C. Прошивка розрахована на адресу
`0x3C` і використовує апаратну шину I2C Arduino Mega:

| Сигнал SSD1309 | Arduino Mega |
|---|---:|
| SDA | 20 |
| SCL | 21 |
| RES | 46 |
| VCC | 5V або 3.3V відповідно до модуля |
| GND | GND |

Лінія `RES` потрібна для надійного запуску фізичного модуля. Перед подаванням
живлення треба перевірити допустиму напругу конкретної плати дисплея.

## Чому в Wokwi інший компонент

Wokwi не має вбудованої моделі SSD1309 2,42″. У схемі використовується
`board-ssd1306` — I2C-дисплей з такою самою роздільною здатністю 128×64.
Він є лише функціональним замінником для перевірки меню, моніторингу,
погоди, кнопок і обміну даними.

Тому фізичний розмір дисплея у Wokwi не відповідає реальним 2,42″. Це
обмеження симулятора, а не електричної схеми чи прошивки.

## Профілі збирання

Проєкт має два середовища PlatformIO:

- `megaatmega2560` — Wokwi та SSD1306-замінник;
- `real-ssd1309` — справжня Arduino Mega та OLED SSD1309 2,42″.

Команди збирання:

```powershell
python -m platformio run -e megaatmega2560
python -m platformio run -e real-ssd1309
```

Завантаження на справжню плату:

```powershell
python -m platformio run -e real-ssd1309 -t upload
```

Обидва профілі використовують бібліотеку U8g2 та спільний код інтерфейсу.
Відрізняється тільки драйвер контролера дисплея, який вибирається під час
компіляції.

## Налаштування фізичного модуля

Деякі плати SSD1309 2,42″ постачаються в режимі SPI. Перед підключенням треба
перевести перемички або нульові резистори модуля в режим I2C відповідно до
інструкції саме його виробника. Модуль повинен мати адресу `0x3C`; після
монтажу це бажано перевірити I2C-сканером.

У Wokwi прошивка з профілем `real-ssd1309` не використовується. Симулятор
завжди запускає файл із каталогу `.pio/build/megaatmega2560/`, як вказано у
`wokwi.toml`.
